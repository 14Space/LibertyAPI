# Журнал решений

Короткие записи: дата, вопрос, ответ, почему так решили.

Первые записи восстановлены задним числом по коду и README (2026-11-18). Дата в них – день
создания проекта (первый коммит). Причины («почему») сформулированы по README и комментариям
в коде, поправь их, если реальные причины были другими. Новые решения записывай сюда в момент,
когда они приняты.

## 2026-11-05. Кто может пользоваться ботом
Вопрос: открыть бота всем или ограничить доступ?
Ответ: доступ только по списку. Один админ (тег в `ADMIN_USERNAME`), остальным доступ выдаёт
админ командой `/giveaccess`. Чужим бот не отвечает вообще.
Почему: модель работает на компьютере владельца и нагружает его, поэтому пользоваться ею
должны только выбранные люди.

## 2026-11-05. Где работает бот
Вопрос: отвечать в группах и каналах или только в личных чатах?
Ответ: только в личных чатах. Сообщения из групп игнорируются, даже от админа.
Почему: у каждого пользователя должен быть свой отдельный контекст разговора, в группе
истории разных людей смешались бы.

## 2026-11-05. Как обрабатываются запросы
Вопрос: отвечать нескольким людям одновременно или по очереди?
Ответ: одна общая очередь, запросы идут по одному, каждый видит своё место.
Почему: в памяти компьютера помещается одна модель, параллельная работа не получится.

## 2026-11-05. Где хранятся данные
Вопрос: облачная база или локальные файлы?
Ответ: всё локально в папке `data/` (база SQLite, логи, резервная копия Bionic). Папка и
`.env` исключены из репозитория через `.gitignore`.
Почему: переписка и токен бота приватные, наружу они не должны попадать. Отдельный сервер
базы для маленького проекта не нужен.

## 2026-11-05. Связь с Telegram
Вопрос: как бот получает сообщения: через webhook или опросом (polling)?
Ответ: опросом, бот сам подключается к Telegram.
Почему: не нужны белый IP и проброс портов, бот работает на обычном домашнем компьютере.

## 2026-11-05. Что делать с моделью в простое
Вопрос: держать модель в памяти постоянно или выгружать?
Ответ: выгружать после простоя (`IDLE_UNLOAD_MINUTES`) и загружать обратно по запросу.
Почему: освобождает память компьютера, когда бот не используется.

## 2026-11-05. Длинные диалоги
Вопрос: что делать, когда история не помещается в контекст модели?
Ответ: старая часть автоматически сжимается в краткий пересказ, свежие сообщения остаются
как есть.
Почему: иначе диалог упрётся в предел контекста и модель перестанет отвечать.

## 2026-11-05. Синхронизация с Bionic
Вопрос: обязательна ли связь с Bionic (сборка LM Studio)?
Ответ: необязательна, включается через `BIONIC_PROJECT`. Если связь не удалась, бот
продолжает работать без неё, ответ не теряется.
Почему: Bionic есть не у всех, а чат админа удобно продолжить на компьютере.

## 2026-11-05. Защита от двойного запуска
Вопрос: что будет, если запустить бота дважды?
Ответ: второй экземпляр не стартует, пока занят локальный порт 49677.
Почему: две копии бота конфликтуют за Telegram и мешают друг другу.

## 2026-11-05. Автоперезапуск
Вопрос: как бот восстанавливается после сбоя?
Ответ: `start.bat` перезапускает его через 10 секунд после остановки.
Почему: бот работает без присмотра, и сбой не должен оставлять его выключенным.
